## 1. 总体方案

R2 主动移动对齐 R1，R1 保持静止。

采用**两阶段分离**策略：
1. **粗对齐**：`waypoint_navigator` 导航至对抗区目标点 (x=−3.0, y=11.6)，完成后切换到视觉伺服
2. **精对齐**：`dock_align_node` 利用 D435i 检测 R1 上的 ArUco 标志，三轴闭环视觉伺服，直到完全对齐

对齐完成后，`game_controller` 发送 ActionGroupCmd（合体动作组），下位机执行合体。

## 2. 算法：三轴视觉伺服（solvePnP）

### 2.1 为什么不用像素位置估距

原始方案用标志在图像中的位置和大小来估算距离，这是透视投影的近似，**误差随角度增大而显著增大**。

D435i 具备深度信息，且可通过 `solvePnP` 直接从 4 个角点给出标志在相机坐标系下的完整 **6-DOF 位姿**（旋转向量 rvec + 平移向量 tvec），精度远高于像素估算，且同时解出了偏航角，无需额外处理。

### 2.2 三个控制自由度

| 误差量 | 来源 | 控制输出 |
|---|---|---|
| `tx` 横向偏移 (m) | `tvec[0]`，正=标志在相机右侧 | `linear.y`（底盘横移） |
| `tz − target_dist` 距离误差 (m) | `tvec[2] − 0.30` | `linear.x`（底盘前后） |
| `yaw_error` 偏航误差 (rad) | 从旋转矩阵 R 提取标志法向在相机 XZ 平面的偏角 | `angular.z`（底盘转向） |

```
yaw_error = atan2(marker_z_in_cam[0], −marker_z_in_cam[2])
# marker_z_in_cam = R[:,2]（标志 Z 轴在相机坐标系中的方向）
# 正对时 ≈ [0,0,−1]，yaw_error ≈ 0；法向偏右时 yaw_error > 0 → 左转
```

### 2.3 控制逻辑

```
① 横向 + 前后同时修正（yaw 始终修正）
② 当横向 + 前后均进入死区后，只剩偏航旋转
③ 三路误差均在死区内连续 CONFIRM_FRAMES 帧 → 发布 status=DONE
```

比例控制（无 I/D）：
```
linear.y  = clip(−kp_lateral  × tx,        ±max_linear)
linear.x  = clip( kp_distance × dist_err,  ±max_linear)
angular.z = clip( kp_yaw      × yaw_error, ±max_angular)
```

### 2.4 多标志支持

支持 R1 上配置多个 ArUco 标志（不同 ID），检测到多个时取**画面最大（即最近）的**参与计算，提高遮挡场景下的鲁棒性。

## 3. R1 上需要准备什么

### 3.1 ArUco 标志贴纸

| 项目 | 建议值 | 说明 |
|---|---|---|
| 字典 | `DICT_4X4_50` | 编码简单，检测速度快，抗干扰性好 |
| 标志 ID | `0`（或多个：`0, 1, 2`） | 对应 `marker_ids` 参数 |
| 边长 | **≥ 8 cm**（建议 10 cm） | 太小远距离检测不稳定；★需用卷尺量实际印刷尺寸填入 `marker_size_m` |
| 数量 | 1～3 个 | 多个分散粘贴提高遮挡鲁棒性 |

### 3.2 标志安装位置要求

- 贴在 R1 正面（朝向 R2 来的方向），高度与 R2 的 D435i 相机（离地约 0.504 m）大致齐平
- 避开强反光材质和大面积同色背景
- 所有标志四周留 ≥ 1 个标志边长的白色边框（ArUco 检测要求）

### 3.3 生成打印标志

```bash
# 生成 DICT_4X4_50 中 ID=0 的标志，保存为 marker_0.png
python3 - <<'EOF'
import cv2
aruco_dict = cv2.aruco.getPredefinedDictionary(cv2.aruco.DICT_4X4_50)
img = cv2.aruco.generateImageMarker(aruco_dict, 0, 400)
cv2.imwrite('marker_0.png', img)
EOF
# 打印时确保最终实物边长 = marker_size_m 参数值
```

## 4. 节点接口

| 话题 | 类型 | 方向 | 说明 |
|---|---|---|---|
| `/dock_align/enable` | `std_msgs/UInt8` | sub | `0`=关闭，`1`=启动 |
| `/dock_align/cmd` | `geometry_msgs/Twist` | pub | 底盘三轴速度指令 |
| `/dock_align/status` | `std_msgs/UInt8` | pub | `0`=搜索中，`1`=伺服中，`2`=完成，`3`=失败 |
| `/camera/camera/color/image_raw` | `sensor_msgs/Image` | sub | D435i 彩色图像 |
| `/camera/camera/color/camera_info` | `sensor_msgs/CameraInfo` | sub | 相机内参（仅加载一次） |

## 5. 启动与测试

```bash
# 仅启动合体对齐节点（调参时开 debug_gui）
ros2 run decision_processor dock_align_node \
    --ros-args \
    -p marker_size_m:=0.10 \
    -p marker_ids:="[0]" \
    -p debug_gui:=true

# 触发对齐（另一终端）
ros2 topic pub /dock_align/enable std_msgs/msg/UInt8 "{data: 1}" --once

# 监听状态
ros2 topic echo /dock_align/status
# 0=搜索  1=伺服中  2=★完成  3=失败

# 关闭
ros2 topic pub /dock_align/enable std_msgs/msg/UInt8 "{data: 0}" --once
```

## 6. 真机调参指南

### 6.1 必须首先确认的参数（不调会出错）

| 参数 | 默认值 | 确认方法 |
|---|---|---|
| `marker_size_m` | 0.10 | **卷尺量实际印刷边长**（不含白边），填入精确值，误差直接影响 tz 距离计算 |
| `marker_ids` | `[0]` | 与 R1 上实际粘贴的 ArUco ID 一致 |
| `target_dist_m` | 0.30 | 根据合体机构接触距离确认：相机到 R2 前端距离 + 合体接口允许裕量 |

### 6.2 比例增益调参（PlotJuggler 辅助）

**工具**：启动 `debug_gui:=true`，同时用 PlotJuggler 订阅 `/dock_align/cmd`

| 增益 | 默认 | 现象 → 调整方向 |
|---|---|---|
| `kp_lateral` | 0.8 | 横移震荡 → 减小；横移太慢/到不了位 → 增大 |
| `kp_distance` | 0.5 | 靠近时超调冲过 → 减小；靠近缓慢 → 增大 |
| `kp_yaw` | 1.2 | 转向震荡 → 减小；偏航修正不收敛 → 增大 |

### 6.3 速度上限

```
max_linear  = 0.15 m/s   # 先从 0.10 开始，确认稳定后增大
max_angular = 0.40 rad/s # 先从 0.20 开始
```

### 6.4 死区调整

死区过小 → 到位后底盘持续微抖；死区过大 → 对齐精度不足

| 参数 | 默认 | 对应物理误差 |
|---|---|---|
| `deadzone_lateral_m` | 0.015 | 横向 ±1.5 cm |
| `deadzone_dist_m` | 0.025 | 距离 ±2.5 cm |
| `deadzone_yaw_rad` | 0.052 | 偏航 ±3° |

根据合体机构的实际对接容差调整（对接容差越大，死区可以越宽，对齐更快稳定）。

### 6.5 方向符号验证（★优先检查）

第一次测试时先在安全环境中以低速（`max_linear:=0.05`）验证：
- 标志在相机右侧时，底盘应向**右**移动（`linear.y` 为负）
- 标志距离超过 `target_dist_m` 时，底盘应向**前**移动（`linear.x` 为正）
- 标志法向偏右时，底盘应向**左转**（`angular.z` 为正）

若任一方向相反，在 `dock_align_node.py` 对应行翻转符号即可（搜索 `kp_lat`/`kp_dist`/`kp_yaw` 前的正负号）。

### 6.6 超时与确认帧数

```
DOCK_ALIGN_TIMEOUT_S      = 30.0  # config.py，对齐总超时
DOCK_ALIGN_CONFIRM_FRAMES = 10    # config.py，连续稳定帧数
```

若场地抖动导致误触发完成 → 增大 `CONFIRM_FRAMES`
若对齐收敛慢、经常超时 → 先检查增益，再适当增大 `TIMEOUT_S`

## 7. 信号流（与 game_controller 集成）

```
game_controller 收到 R1Signal(合体指令)
        ↓
发布 /dock_align/enable = 1
        ↓
dock_align_node 开始三轴视觉伺服
        ↓
/dock_align/status = 2 (DONE)
        ↓
game_controller 发送 ActionGroupCmd(合体动作组)
等待 ActionGroupFeedback(完成)
        ↓
发布 /dock_align/enable = 0  关闭节点
        ↓
合体完成，进入下一阶段
```
